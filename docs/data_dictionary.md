# Data dictionary

All data is **synthetic**, generated by `src/fpa/generate/` for a fictional B2B SaaS company ("Altair Cloud, Inc.") with three legal entities (US, UK, Germany). The generator simulates a hidden "true" business through 2031. The `as_of` date controls which months have been closed and released, so history never changes as the demo rolls forward.

## Raw layer (`data/raw/`, regenerated deterministically, not committed)

| File | Source system | Grain | Key columns |
|---|---|---|---|
| `gl_journal_lines.csv` | ERP general ledger | one row per journal-entry line | `je_id`, `line_no`, `period` (YYYY-MM), `posting_date` (MM/DD/YYYY), `entity`, `account`, `cost_center`, `vendor_id`, `vendor_name`, `customer_id`, `document_number`, `description`, `debit`, `credit` (blank = 0), `currency`, `source` (AP/AR/REVREC/PAYROLL/ACCRUAL/FA/MANUAL), `created_by`, `is_reversal` (Y/N) |
| `gl_control_totals.csv` | ERP | period × entity | `line_count`, `total_debit`, `total_credit`: the ERP's own totals, used to reconcile the load |
| `chart_of_accounts.csv` | ERP master data | account | `account_type` (Asset/Liability/Revenue/Cost of Revenue/Operating Expense), `fs_line` (P&L line; blank for balance-sheet accounts), `normal_balance` |
| `cost_centers.csv` | ERP master data | cost center | `department`, `function` (S&M, R&D, G&A, Cost of Revenue, Revenue), `entity`, `budget_owner` |
| `vendors.csv`, `entities.csv` | ERP master data | vendor / entity | vendor category; entity functional currency |
| `fx_rates.csv` | Treasury | period × currency | `usd_per_unit` (monthly average) |
| `budget_fyYYYY.csv` | FP&A planning tool | period × entity × account × cost center | `version` (e.g. AOP FY2026), `released_on` (15-Nov of the prior year), `amount_usd` |
| `hris_headcount.csv` | HR system | period × cost center | `headcount`, `hires`, `terminations` |
| `hris_headcount_plan.csv` | HR / FP&A | period × cost center | `planned_headcount` per released plan |
| `crm_arr.csv` | CRM | period × entity | ARR bridge: `beginning_arr`, `new_arr`, `expansion_arr`, `contraction_arr`, `churn_arr`, `ending_arr`, `customers` |
| `_answer_key.json` | *hidden* | anomaly | injected anomalies and their affected P&L lines/months. **Never read by the pipeline**, only by the evaluation step and the tests |

### Deliberate realism and messiness
- Every journal entry balances. Month-end accruals reverse on day 1 of the next month when the invoice arrives. Payroll posts twice a month, bonuses and commissions are accrued, and quarter-end manual reclasses correct miscoded licences.
- Extract duplicates (an overlapping extract window) put some journal entries out of balance until they are de-duplicated.
- Blank or invalid cost centers on some AP lines are imputed from each vendor's usual coding.
- Inconsistent vendor-name casing and padding, upper-cased descriptions, US-format dates and blank zeros.
- Storylines: COVID-era travel in 2021, a hiring freeze (Nov-22 to Mar-23), a move to a new HQ (Jul-23), the largest customer churning (Jul-24), and a price increase applied at renewal (Jul-25 to Jun-26).
- Budget behaviour: stretch growth targets, a hiring plan that assumes no recruiting lag, flat phasing for some lines, and per-line planning errors.

## Warehouse (`data/warehouse/fpa.duckdb`, built by `sql/`)

| Table | Description |
|---|---|
| `stg_gl_lines` | de-duplicated, standardised GL lines with imputed cost centers and USD amounts (`amount_usd` = local × monthly rate, in cents) |
| `stg_budget`, `stg_headcount`, `stg_headcount_plan`, `stg_arr` | typed staging copies of the other extracts |
| `fct_gl_pnl_lines` | P&L lines only, with reporting attributes; sign convention: revenue and costs both positive |
| `fct_monthly_pnl` | **forecast grain**: period × `fs_line` × `department` (27 series) |
| `fct_budget_monthly`, `fct_headcount`, `fct_arr` | budget, headcount (actual vs plan) and ARR at the same grain |

## Marts (`data/marts/`, committed, read by the app)

| File | Description |
|---|---|
| `fct_monthly_pnl`, `fct_budget_monthly`, `fct_headcount`, `fct_arr` | exported from the warehouse |
| `gl_detail_recent` | P&L journal lines for the last 13 months (drill-down) |
| `series_meta` | one row per series (`unique_id` = "P&L line \| department") |
| `forecast_vintages` | every model's forecast from every origin (24 backtest origins + the live one): `origin`, `ds`, `horizon`, `model`, `yhat`, `y` (actual when known), `is_champion`, `lo80/hi80/lo95/hi95` (champion only) |
| `forecast_live` | champion forecast from the latest close, with budget |
| `champions`, `champion_history` | current champion per series, and the champion chosen at each origin using only information available then |
| `leaderboard` | WAPE and bias per series × model × horizon bucket |
| `accuracy_summary`, `accuracy_by_series`, `accuracy_by_horizon`, `accuracy_by_group` | out-of-sample accuracy of the rolling forecast vs the static budget over the last 12 closed months |
| `fy_outlook` | full-year landing estimate: YTD actuals + remaining forecast vs FY budget |
| `cleaned_history` | training series after one-off spikes are dampened |
| `lgb_importance` | LightGBM feature importance (gain share) |
| `variance_monthly` | series × last 12 months: actual, budget, last forecast and expected range, prior year, variances, `material`, `outside_range`, `drift_months`, `severity` (Red/Amber/Green), `commentary`, `drivers` (JSON), `personnel_split` (JSON) |
| `variance_ytd` | year-to-date variance vs budget with YTD materiality |
| `flag_evaluation` | each injected anomaly in the window and the best flag it received |
| `run_metadata.json` | as-of period, data-quality report, reconciliation checks, headline metrics |
